# Launch-day checklist (Show HN day — the peak beat)

Run this only after Phase 0–2 are done (assets polished, soft launch shipped, first-impression rough edges fixed). You get one good Show HN; treat it like a launch, not a post.

## T-minus 1 week
- ☐ Demo GIF + MP4 live in README and landing page
- ☐ Quickstart verified on a **clean machine** (fresh VM/container — the #1 way to lose new users is a broken `pipx install`)
- ☐ Landing page: one clear CTA, demo above the fold, links work
- ☐ GitHub Discussions **enabled**; 2–3 seed threads (Q&A, "roadmap", "show us what you built")
- ☐ 30–50 honest stars seeded; a few Discussions/issues so the repo doesn't look empty
- ☐ CONTRIBUTING + "good first issue"s labeled
- ☐ UTM links built for each channel (so you can see what converts)
- ☐ Comparison page published (the "why not LangGraph" link)

## T-minus 1 day
- ☐ Pick the Show HN title (see `social/show-hn.md`); keep it plain and honest
- ☐ Draft the first comment; have it ready to paste the instant you post
- ☐ Clear your calendar for the launch morning + 8 hours after
- ☐ Line up a few people who'll genuinely engage (not vote-ring — engage: read, comment, ask real questions)
- ☐ Status page / server headroom if the landing page is self-hosted

## Launch morning (Tue–Thu, ~8–10am ET)
1. ☐ Post **Show HN** → immediately paste your first comment (the why + what's early)
2. ☐ Do **not** ask for upvotes anywhere (fastest way to get flagged/penalized)
3. ☐ Post the **X launch thread** (demo video first)
4. ☐ Post the **LinkedIn** (platform-team framing)
5. ☐ **Reddit stays staggered** — do *not* fire all subs today; space them over the following days (see `social/reddit.md`)
6. ☐ Reply to **every** HN comment — fast, substantive, non-defensive. Concede real limitations; it builds credibility.

## During (first 8 hours)
- ☐ Watch: HN rank/comments, GitHub stars (real-time), PyPI installs, landing referrers
- ☐ Triage issues opened by new users *immediately* — a fast fix on launch day is worth 100 stars
- ☐ Screenshot milestones (front page, star spikes) for later social proof
- ☐ Keep answers technical and humble; if someone says "this is just LangGraph + X," engage with the real distinction, don't get defensive

## After
- ☐ Thank the thread; write a short "what we learned from launch" follow-up (another content beat)
- ☐ Log every feature request / objection → roadmap + future comparison-page updates
- ☐ Convert engaged commenters → Discussions/Discord → contributors
- ☐ Schedule the **next beat** (0.4.0 notes, a cookbook tutorial) ~2 weeks out — momentum compounds

## Hard don'ts
- ✗ Don't post identical text to multiple subreddits (bans)
- ✗ Don't ask for upvotes / vote-ring (HN + Reddit both penalize hard)
- ✗ Don't over-claim ("production-ready", invented benchmarks) — this audience checks
- ✗ Don't launch and walk away — presence *is* the strategy
